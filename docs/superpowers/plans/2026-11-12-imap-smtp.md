# IMAP/SMTP Provider and Attachment Reads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a generic IMAP/SMTP mailbox provider (password login) next to Gmail, with the same MCP tools and
invariants, plus attachment reads for both providers.

**Architecture:** A new `src/imap/` module owns the only IMAP/SMTP wire code (typed operation allowlist, connection
pool, SMTP submission). A thin provider-neutral layer (`src/mail.rs`) gives tools one `fetch_message`/`list_labels`
API and dispatches on `Mailbox.provider`. IMAP messages are presented to the index and tools with Gmail-compatible
system labels (`UNREAD`, `STARRED`, `DRAFT`, `TRASH`, `SPAM`) plus the folder path, so index queries and filter
booleans stay unchanged.

**Tech Stack:** Rust 2024, tokio, tokio-rustls / rustls 0.23 (the stack reqwest already uses), `async-imap`
(tokio runtime, verify current version and licence in `~/.cargo/registry` or crates.io before adding) for IMAP, a
small hand-written SMTP client (needed for exact outcome classification), existing `mail-parser`/`mail-builder`.

**Spec:** `docs/superpowers/specs/2026-11-12-imap-smtp-design.md` (amends `docs/spec.md`). Read both, plus AGENTS.md.

## Global Constraints

- All AGENTS.md security invariants hold: one `policy::authorize`, exactly one audit record per tool call, identical
  `not_found`, no mail content / addresses / subjects / passwords in logs or audit, no SQLite transaction across
  network I/O (`spawn_blocking` for DB work), secrets only from files or the vault.
- Password: never in argv, env, logs, audit, error texts or plaintext state. `Zeroizing` everywhere it is held.
- TLS verified against platform roots (same verifier setup reqwest uses). Plaintext exists only through a constructor
  behind the `testing` feature, used by `tests/support`. No config key can turn verification off.
- IMAP commands only from the allowlist in the design ("Command allowlist"); reads use `BODY.PEEK` only; `STORE`/
  `EXPUNGE` only through a `OwnDraftUid` newtype that only `tools/drafts` can construct (pattern: `SendPermit`).
- Required capabilities: `IMAP4rev1`, `UIDPLUS`; Drafts folder via `SPECIAL-USE` or names Drafts, Entwürfe, Draft
  (override `--drafts-folder`). Missing UIDPLUS refuses connect.
- Presets: Strato (`strato.de` and any domain the operator marks `--preset strato`) `imap.strato.de:993` implicit,
  `smtp.strato.de:465` implicit; iCloud (`icloud.com`, `me.com`, `mac.com`) `imap.mail.me.com:993` implicit,
  `smtp.mail.me.com:587` STARTTLS, `save_sent_copy = false`.
- Message id format `f<folder_id>-<uidvalidity>-<uid>`; must pass `gmail::gateway::valid_id`.
- Attachment limit `limits.attachment_bytes` default 10 MiB (10 * 1024 * 1024); audit size classes `<1MiB`,
  `<10MiB`, `too_large`.
- Per-account IMAP connections: default 2, idle timeout 60 s.
- Commands: `export PATH=$HOME/.cargo/bin:$PATH`; one test file `cargo test --test <f>`; full suite only as
  `CARGO_BUILD_JOBS=3 heavy cargo test -- --test-threads=2`; `cargo clippy --all-targets -- -D warnings`; `cargo fmt`.
  Use a private target dir per worktree (AGENTS.md). Break code on purpose to see each new test fail; record the
  mutation in the commit message body.
- Docs in English. Every durable learning goes into AGENTS.md "Learnings" in the same commit.

## Review Focus

1. Server rewrites appended draft bytes (CRLF normalisation, added headers): fresh check must not report a false
   `draft_conflict`. Test: fake server that rewrites on APPEND; update after create succeeds (Task 5).
2. Non-ASCII folder names (modified UTF-7, e.g. `Entw&APw-rfe`): Drafts detection and agent-visible label must be
   decoded UTF-8. Test in Task 1 (decode) and Task 2 (connect finds `Entwürfe`).
3. Connection dropped mid-FETCH or mid-APPEND: pool must discard the session, never reuse a half-read stream; APPEND
   loss maps to unknown outcome. Test: fault `DropAfterApply` on APPEND (Task 5), drop during FETCH then a second call
   succeeds (Task 1).
4. Password with quotes, backslash, non-ASCII: login must work (literal or AUTHENTICATE PLAIN). Test in Task 1.
5. Very large mailbox / message over limits: backfill stays bounded in memory, oversize messages indexed from metadata
   only, `get_attachment` over limit returns `too_large` without fetching more than needed. Tests in Tasks 3 and 4.
